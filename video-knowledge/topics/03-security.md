# 3. אבטחה

**סקיל:** [`security-hardening`](../skills/security-hardening/SKILL.md) · **סרטונים:** 023, 026, 034, 040, 041, 048, 053, 057, 058, 061, 066, 071, 073, 076, 077, 084, 099

## העיקרון
Claude הולך על הדרך הכי מהירה, אלא אם אומרים לו אחרת. ומאז שיש AI, קל גם לתוקפים למצוא חורים.

## מה יש בנושא

### סודות ומפתחות
- אסור שיהיו מפתחות API בקוד שהדפדפן טוען. כל מי שלוחץ F12 יכול להעתיק אותם (057, 058)
- `.env` נכנס ל-`.gitignore` לפני הקומיט הראשון, ובודקים גם את היסטוריית git (023, 071)
- אם מפתח דלף, **מחליפים אותו קודם**. למחוק את הקומיט לא מספיק (071)
- **hook שחוסם את Claude Code מלקרוא `.env`**, כי מה שהוא קורא נשמר במחשב (099)

### הזדהות והרשאות
שירות התחברות מוכן ולא בנוי לבד · גיבוב סיסמאות (argon2/bcrypt) · אימות דו-שלבי · קישור איפוס שפג תוקפו · עוגיות מאובטחות · בדיקת הרשאות בשרת · לא סומכים על user ID שמגיע מהלקוח (023, 026, 041, 071)

### מסד נתונים
- **RLS על כל טבלה** ב-Supabase, וכללי אבטחה אמיתיים ב-Firebase
- **בדיקה: נכנסים כמשתמש A ומנסים לקרוא את המידע של B** (071)
- Parameterized queries או ORM בלבד, אחרת SQL injection (066)
- גיבויים, ובודקים שאפשר באמת לשחזר מהם

### קלט, כסף וניצול לרעה
- ולידציה בשרת · הגנה מ-XSS ו-CSRF · הגבלת סוג וגודל של קבצים
- **מחשבים את המחיר בשרת**, כדי שאף אחד לא יהפוך מוצר של 50 שקל לשקל אחד (026, 041)
- **Rate limiting**: שכבה בקצה (Cloudflare) ועוד שכבה בקוד, לפי משתמש ולא רק לפי IP (076)
- **תקרת הוצאה על AI** לכל משתמש (026)

### סוכני AI בתוך האפליקציה (Prompt injection) (061)
1. רק את ההרשאות שהסוכן חייב
2. שליחה, תשלום ומחיקה רק באישור אדם
3. סוכן שקורא תוכן מבחוץ לא פועל לבד
- הבוט מוגן לא בגלל שהוא חכם, אלא כי **אין לו מה לגנוב**

### תהליך
- בכל שינוי בקוד פותחים session חדש ושואלים "יש פה חור אבטחה?" (048)
- סריקה של חבילות קוד פתוח, כלומר שרשרת האספקה (048)
- סקירת PR אוטומטית עם AI, למשל Greptile (053)
- בדיקה מלאה שמחזירה טבלת ממצאים עם קובץ ושורה. באחד הסרטונים היא מצאה 12 ממצאים, אחד מהם חמור (084)
- OWASP Top 10, ובסוף "תנסה לפרוץ לעצמך" (026, 071)
