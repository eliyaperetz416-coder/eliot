# מה עושים כשמשהו משתבש

הדף הזה נשאר קצר בכוונה. בכל מקרה אפשר לפתוח שיחה עם Claude ולכתוב "תפתח את docs/EMERGENCY.he.md ותעזור לי עם מקרה X".
אין בדף שום סיסמה או מפתח, והוא יכול להישאר בריפו הציבורי.

## 1. עלתה גרסה שבורה של האתר
1. **vercel.com**, אחר כך הפרויקט **eliot**, אחר כך **Deployments**.
2. מוצאים את הגרסה הציבורית (Production) הקודמת, זו שעבדה, ובתפריט ⋯ שלה לוחצים **Instant Rollback**. האתר חוזר אליה תוך שניות.
3. טלפונים שכבר קיבלו את הגרסה השבורה יקבלו את הישנה בפתיחה הבאה, דרך ההודעה "גרסה חדשה מוכנה".
4. **אם האפליקציה תקועה אצל אנשים ולא מגיעה להודעה:** ב-`sw.js` יש מתג חילוץ `RESCUE`. מעלים אותו ל-`true` לגרסה אחת בלבד, והיא משתלטת מיד בלי לשאול. בגרסה שאחריה מחזירים ל-`false`. את זה עושים רק עם Claude.

## 2. המידע של מישהו נמחק או התקלקל
- **השרת שומר את 3 הגרסאות האחרונות** של כל משתמש, ועוד גרסה אחת לכל אחד מ-7 הימים האחרונים (בטבלה `app_private.user_data_history`).
- **חשבון שנמחק** נשמר 24 שעות בטבלה `app_private.deleted_accounts`, יחד עם המייל.
- **גיבוי לילי של כל המסד** נמצא בריפו הפרטי `eliot-backup`: נכנסים ל-**Actions**, אחר כך **Daily backup**, בוחרים ריצה, ושם תחת **Artifacts**. כל גיבוי נשמר 30 יום.
- מבקשים מ-Claude: "תחזיר את המידע של המשתמש X לגרסה מלפני Y". תמיד קודם ניסיון יבש ורק אחר כך שחזור אמיתי.

## 3. נראה שמישהו פרץ
1. **קודם סוגרים את הדלת:**
   - מחליפים סיסמה בגוגל וב-GitHub.
   - ב-GitHub, בעמוד **Settings**, אחר כך **Sessions**, מנתקים כל מכשיר שאתה לא מכיר.
   - בודקים את **Tokens**, **SSH keys** ו-**Applications**, ומוחקים כל מה שזר.
2. **מחליפים מפתחות בשרת** (עם Claude):
   - `notify_secret`: הסוד שמאפשר לשלוח התראות.
   - סיסמת מסד הנתונים: Supabase, אחר כך **Connect**, ואז **Reset database password**. אחר כך מעדכנים את הסוד `SUPABASE_DB_URL` בריפו `eliot-backup`.
   - אם צריך: מפתחות ההתראות (VAPID). אחרי החלפה כזו, כל טלפון צריך להפעיל התראות מחדש.
3. **בודקים מה קרה:**
   - **יומן האבטחה**, `app_private.audit_log`, נשמר 30 יום. יש בו מחיקות חשבון, פתיחות של קבוצות, הצטרפויות ועזיבות, ושמירות חשודות. לכל פעולה יש זמן, IP וסוג דפדפן.
   - הלוגים של Supabase נשמרים רק 24 שעות, אז כדאי להסתכל בהם מהר.
   - ב-Vercel, תחת Deployments: האם עלתה גרסה שלא אתה מיזגת?
4. **בודקים את הנתונים:** משחזרים מהגיבוי של הלילה שלפני הפריצה. ראה סעיף 2.

- מבקשים מ-Claude לבדוק את המשימות המתוזמנות של השרת (`demigod-*`) ואת הלוגים של שירות ההתראות `rest-push`.

## 5. הגיבוי הלילי נכשל
GitHub שולח מייל. כמעט תמיד הסיבה היא שהסיסמה של המסד השתנתה. מעדכנים את הסוד `SUPABASE_DB_URL` בריפו `eliot-backup`, ואז ב-**Actions**, ב-**Daily backup**, לוחצים **Run workflow** כדי לבדוק.
